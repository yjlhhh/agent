# DeepSearch OpenAI 風格 UI 重設規格

日期：2026-08-02  
狀態：視覺與技術方向已確認，待使用者審閱書面規格

## 1. 目標

將目前的 SalesPilot／DeepSearch 混合介面統一為 **DeepSearch**，打造桌面優先、簡體中文、淺色主題的 AI 搜尋與研究產品。

介面參考 OpenAI 產品的核心設計原則：

- 大量留白與單一視覺焦點
- 內容優先，降低卡片、邊框和裝飾噪音
- 清楚且穩定的長文閱讀節奏
- 研究過程透明，但不暴露模型原始內部推理
- 來源、圖片和工具活動可追溯且按需展開

本次不複製 OpenAI 品牌識別；DeepSearch 保留自己的名稱、研究能力與資訊架構。

## 2. 已確認決策

- 產品定位：通用 AI 搜尋／研究工具 DeepSearch
- 主要方向：研究過程內嵌
- 過程透明度：預設精簡里程碑，點開後顯示搜尋、工具與來源活動
- 裝置策略：桌面優先，小螢幕僅維持基本可用
- 功能範圍：重設 UI，並補齊核心聊天互動與來源展示
- 主題：首版只做淺色主題
- 介面語言：簡體中文

## 3. 範圍

### 3.1 本次包含

- 首頁／空對話頁
- 聊天與回答頁
- 研究進度與活動詳情
- 圖片、Markdown、程式碼、引用與來源
- 對話歷史入口
- 知識庫頁的視覺統一
- 充值頁移除全螢幕 iframe，改為主 Layout 內的簡潔頁面
- 停止生成、複製、重試、回饋和來源查看
- 串流狀態、錯誤狀態與捲動行為
- 基礎自動化測試與桌面視覺驗收

### 3.2 本次不包含

- 完整手機版重設
- 深色主題
- 登入、帳務或付款後端重構
- 全新的研究模型或搜尋演算法
- 展示模型原始 chain-of-thought
- 與 UI 重設無關的後端大規模重構

## 4. 視覺方向

### 4.1 首頁

首頁只有一個主要任務：開始提問。

- 全畫布白色背景，不常駐側欄
- 左上提供選單入口，展開後顯示歷史對話、知識庫和設定
- 中央顯示簡短問候與膠囊輸入框
- 輸入框是唯一高對比元素
- 快捷入口使用低對比文字與圖示，不使用大型任務卡
- 頁尾以低對比文字提示使用者核查重要資訊

首頁視覺稿：

- `.superpowers/brainstorm/45876-1785641667/content/openai-home-v2.html`

### 4.2 回答頁

回答內容沿單一閱讀軸自然展開，介面元件不搶奪內容焦點。

- 內容最大寬度 760px
- 使用者問題靠右顯示為低對比氣泡
- 研究過程縮成一行摘要，可展開查看活動
- 高相關圖片存在時使用三聯圖開場；沒有圖片時不保留空白
- Markdown 標題、正文、引用與程式碼沿同一閱讀軸排列
- 程式碼區塊使用淺灰背景，只保留必要的複製操作
- 正文引用使用輕量數字標記
- 完整來源集中於回答末尾或抽屜
- 輸入框固定於底部；離開底部時顯示浮動向下按鈕

回答頁視覺稿：

- `.superpowers/brainstorm/45876-1785641667/content/openai-answer-v2.html`

### 4.3 知識庫

- 與主應用共用 App Shell、字體、間距與控制樣式
- 提供搜尋、類型篩選、排序與上傳入口
- 清楚顯示解析中、可用、失敗與可重試狀態
- 表格外觀降低 Ant Design 預設風格，保持輕量

### 4.4 充值頁

- 移除固定定位的全螢幕 iframe
- 使用主應用 Layout 內的方案與權益卡
- 首版只處理視覺整合，不改造付款後端

## 5. 設計系統

### 5.1 色彩

- 主背景：`#FFFFFF`
- 次層背景：`#F7F7F5`
- 主文字：`#202020`
- 次文字：`#73736F`
- 邊框：`#E2E2DF`
- 主要操作：`#111111`

邊框只用於輸入框、程式碼、必要分隔與互動控制，不用於包裝每段內容。

### 5.2 排版

- 字體：Inter、Noto Sans SC、系統中文字體
- 正文：15px，行高 1.7
- 主要標題：22–28px，緊湊字距
- 次級標題：18–22px
- 輔助文字：11–13px
- 內容最大寬度：760px

### 5.3 間距、圓角與動效

- 基礎間距：4px
- 常用間距：8、12、16、24、32px
- 輸入框圓角：24px
- 一般控制圓角：8px
- 內容區塊圓角：14–16px
- 動效時間：150–220ms
- 動效只用於抽屜、展開、生成狀態、hover 與焦點變化

### 5.4 無障礙

- 所有操作均可使用鍵盤完成
- 焦點樣式清楚可見
- 文字與控制對比度符合 WCAG AA
- 純圖示控制必須提供可讀標籤與 Tooltip
- 動畫遵守 `prefers-reduced-motion`

## 6. 前端架構

保留 React、Vite、React Router、Valtio、Ant Design 與現有後端 API，不重寫技術棧。

### 6.1 核心元件

- `AppShell`
  - 管理頂部列、導航抽屜與頁面容器
- `NavigationDrawer`
  - 顯示新對話、歷史對話、知識庫、充值與設定
- `PromptComposer`
  - 首頁與聊天頁共用
  - 處理附件、深度研究、聯網、提交與停止
- `MessageList`
  - 管理訊息順序與捲動容器
- `AssistantResponse`
  - 組合研究摘要、圖片、Markdown、引用、來源與操作
- `ResearchActivity`
  - 預設顯示一行摘要
  - 展開後顯示可驗證的工具與來源活動
- `MediaGallery`
  - 依資料量決定單圖、雙圖或三聯圖版面
- `MarkdownContent`
  - 統一標題、清單、表格、程式碼與引用排版
- `Citation`
  - 對應來源並開啟 `SourceDrawer`
- `SourceDrawer`
  - 顯示來源標題、摘要、URL 與對應引用
- `ResponseActions`
  - 複製、重試、回饋與更多操作

### 6.2 樣式策略

- 建立全域 design tokens
- 頁面與元件使用 CSS Modules
- Ant Design 只保留 Dialog、Tooltip、Upload、Popover 等基礎能力
- 透過 `ConfigProvider` token 與局部 class 統一視覺
- 移除散落的 inline style 與重複全域覆寫

### 6.3 串流責任分離

聊天頁不直接解析 SSE。新增獨立串流層：

- SSE parser：將原始資料轉為標準事件
- stream reducer：管理回答狀態
- `useChatStream`：管理請求、取消、重連與狀態更新
- UI 元件只接收標準化資料，不依賴後端原始欄位格式

## 7. 回答資料流

狀態流程：

`idle → submitting → researching → streaming → completed | stopped | failed`

### 7.1 事件處理

- `thinking`
  - 不直接渲染原始內容
  - 只映射為「理解問題、搜尋資料、交叉驗證、組織結論」等可公開摘要
- `content`
  - 逐段累積並穩定渲染
- `documents`
  - 標準化為來源模型，提供引用與抽屜使用
- `image_results`
  - 驗證後交給 `MediaGallery`
- `video_results`
  - 只在存在有效資料時顯示
- `recommended_questions`
  - 回答完成後顯示為低對比追問

### 7.2 停止與重試

- 每個請求由 `AbortController` 管理
- 停止後保留已生成內容並標示「已停止」
- 重試建立新的回答版本，不覆寫原回答
- 使用者可切換不同回答版本

### 7.3 捲動

- 使用聊天容器捲動，不操作 `document.documentElement`
- 使用者位於底部時才自動跟隨新內容
- 使用者向上閱讀時暫停自動捲動
- 有新內容時顯示浮動向下按鈕

## 8. 錯誤與空狀態

- 提交失敗：保留輸入內容並允許重送
- 串流中斷：保留部分回答，顯示重連或重新生成
- 來源為空：不渲染來源入口
- 圖片為空或失敗：不保留圖片區域
- Markdown 解析失敗：退回安全純文字
- 知識庫解析失敗：顯示原因與重試
- 無歷史對話：導航中顯示簡潔空狀態
- 404：提供返回首頁與新對話入口

所有錯誤應在發生位置附近呈現，不使用與上下文脫離的全域錯誤頁。

## 9. 安全

- Markdown HTML 必須清理，不直接信任後端內容
- 外部連結使用安全的 `rel` 屬性
- 不在前端展示原始模型 chain-of-thought
- 來源 URL 與媒體 URL 在渲染前驗證
- 上傳檔案沿用後端類型與大小限制，前端提供一致提示

## 10. 測試與驗收

### 10.1 單元測試

- SSE 行解析與跨 chunk 組合
- 非法 JSON 與未知事件
- stream reducer 的所有狀態轉換
- 引用與來源映射
- 推薦問題資料清理

### 10.2 元件測試

- `PromptComposer` 提交、停止與模式切換
- `ResearchActivity` 收合與展開
- `MediaGallery` 在 0–3+ 張圖片下的版面
- `AssistantResponse` 條件渲染
- `SourceDrawer` 引用定位
- 錯誤、停止與重試狀態

### 10.3 整合測試

- 一般 SSE 回答
- 深度研究 SSE 回答
- 使用者中止
- 網路中斷與重試
- 空來源、空圖片與部分資料
- 歷史回答載入

### 10.4 視覺與手動驗收

- 1440px 桌面寬度下驗收首頁、生成中、完整回答與知識庫
- 檢查長回答、長程式碼、超長 URL 與中英文混排
- 檢查鍵盤導航、焦點、Tooltip、對比度與 reduced motion

### 10.5 建置門檻

- TypeScript 通過
- ESLint 通過
- 自動化測試通過
- Vite 生產建置通過

## 11. 成功標準

- 首頁第一視覺焦點明確落在輸入框
- 回答頁沒有不必要的卡片與邊框
- 長文、圖片、程式碼與引用的閱讀節奏一致
- 串流內容不產生明顯版面跳動
- 停止與重試行為可靠
- 研究活動可追溯但預設不干擾閱讀
- 來源可由正文引用定位
- 不展示模型原始內部推理
- 核心頁面在桌面寬度下視覺一致
